# 인쇄물 조판과 검수

## 1. 적용 원칙

- 활동지·퀴즈·해설은 단순한 텍스트 PDF가 아니라 인쇄용으로 조판한다.
- 문제지는 수능형 제목·문항 번호·명조체·중앙 구분선·넉넉한 풀이 공간을 기본으로 한다. 문제 내용·기관 로고·공식 시험 명칭·배점은 모방하지 않는다.
- 내용이 같아도 문항 성격과 학년에 따라 칸 크기를 바꾼다. 소인수분해 예시의 문항 수·쪽수·답란 높이를 다른 단원에 고정하지 않는다.
- 가독성 우선순위: 글자 크기와 풀이 공간 → 수식·그림의 온전함 → 문항 간 구분 → 쪽수 절약. 본문을 작게 줄이거나 답란을 없애서 한 쪽에 맞추지 않는다.
- 재조판 요청이면 문제·정답·난이도는 유지하고 기존 파일을 보존한다. 파일명에 `_개선_v2` 등 수정본임을 표시한다.

## 2. 재사용 CSS

`assets/exam-print.css`가 정밀 인쇄의 기본 스타일이다. 필요한 부분만 수정하고 HTML 안에 인라인으로 포함하거나, 유효한 로컬 상대 경로로 연결한다.

- `@page`: A4 세로, 여백 0. 대신 `.sheet` 자체에 위 15mm·좌우 16mm·아래 20mm 안팎의 패딩을 둔다. **다른 CSS의 @page 여백과 이중 적용하지 않는다.**
- `.sheet`: A4 한 쪽. 자식 `.content`에 본문, 형제 `.footer`에 하단 문구·쪽수·자료 종류를 넣는다. 실제 내용마다 쪽을 명시적으로 나눈다.
- `.kicker`, `.mainhead`, `.identity`: 작은 머리말, 과목/영역 제목과 자료 종류, 이름·번호 빈칸.
- `.exam-columns`: 2단과 중앙 구분선. 왼쪽 문항을 먼저, 오른쪽 문항을 나중에 넣어 읽기 순서와 PDF 추출 순서를 맞춘다.
- `.question`, `.stem`, `.num`, `.bank`: 문항 단위, 질문, 큰 번호, 보기/수 집합 영역. `.q1`~`.q5`의 높이는 짧은 5문항 배치 예시일 뿐이며 실제 문항에 맞춰 조정한다.
- `.work`: 무선 계산 공간. `.line`과 `.ruleline`: 기입 칸과 실제 border 답안선. 7~8mm 간격이 기본이다. 답안선은 반복 그라디언트 대신 여러 요소의 border로 그린다.
- `.drawing`, `.treeblank`, `.activitycard`: 점 격자/그림 공간, 분해 공간, 나란히 비교할 활동 칸.
- `.answerhead`, `.answerchip`, `.answerbody`, `.feedback`: 문항 제목, 먼저 보이는 정답, 풀이·오개념, 구분된 되묻기 발문.
- `.schedule-row`, `.time`, `.ask`: 교사용 수업 단계, 소요 시간, 대응 발문.
- `.footer`: 하단 별도 영역. 매 쪽에 `※ 초안입니다. 수업 전 반드시 검토하세요.`와 쪽수·학생용/교사용 구분을 넣는다.
- `assets/a4.css`는 단순 자동 흐름 문서의 대체 스타일이다. 정밀 `.sheet` 조판에 함께 적용하지 않는다.

## 3. 글꼴·수식·인쇄

- 본문: 본명조(Noto Serif KR/Source Han Serif), 나눔명조 등 한글 명조 계열. 보통 11~12pt, 줄 간격 1.55~1.75. 저학년은 12~14pt 이상과 1단을 우선 검토한다.
- 제목·문항 번호·구분 라벨: 고딕 계열. 제목 21~26pt 안팎, 문항 번호 14pt 안팎으로 위계를 만든다.
- 수식: 숫자·곱셈기호·지수를 명료하게 표시한다. 짧은 식은 `.math`로 묶어 중간 줄바꿈을 막는다. 긴 식은 등호 기준으로 의도적으로 여러 줄에 나눈다. 한 단 너비보다 긴 수식 전체를 nowrap으로 묶지 않는다.
- 한글 명조를 사용할 수 없으면 글꼴을 확보하거나 대체 적용 사실을 밝힌다. 구두점·지수·한글을 실제 출력에서 확인한다.
- 웹폰트는 공식 배포처/공식 CSS API에서 확보하고 PDF 출력 전 로딩을 완료한다. 임시 HTML에 로컬 파일 또는 data URI로 포함하면 만료·네트워크 실패를 줄일 수 있다.
- **한 문서의 글자만 들어 있는 웹폰트 서브셋을 범용 글꼴로 스킬에 저장하지 않는다.** 서브셋을 쓰면 새 자료의 모든 글자를 기준으로 새로 생성한다. 글꼴·라이선스는 각각의 공식 배포 조건을 따른다.
- 코딩 경로에서는 `LESSON_FONT_FILE`, `LESSON_FONT_FAMILY`로 명조 글꼴을 지정할 수 있다. 자동으로 선택된 고딕 글꼴만으로 명조 조판을 완료했다고 하지 않는다.
- 검정·회색을 중심으로 한다. 강조색을 써도 흑백 인쇄에서 선·명암·제목 위계로 구분되어야 한다. 넓은 진한 배경이나 과도한 장식은 피한다.

## 4. Aside 제작 경로

1. 임시 폴더에 HTML과 필요한 CSS·글꼴을 준비한다. 루프백 로컬 서버로 열고 스냅샷으로 내용·쪽 구성을 확인한다. HTML은 중간물이며, 사용자가 원하지 않으면 결과물로 제공하지 않는다.
2. 폰트 로딩 후 페이지 검사를 실행한다. 아래 코드는 스킬 폴더의 실제 절대 경로로 읽는다.

```js
const layoutCheckCode = await fs.readFile(skillDir + '/scripts/check-print-layout.js', 'utf8');
const layoutReport = await page.evaluate(layoutCheckCode);
console.log(layoutReport);
```

3. `ok: false`이면 수정한다. `.content`와 하단 문구 사이 최소 2mm 정도를 확보한다. 글씨 축소보다 제목·장식·문단 간격 재배분, 문항 이동, 쪽 추가를 먼저 검토한다.
4. `page.pdf({path: pdfPath, preferCSSPageSize: true, printBackground: true})`로 아티팩트 폴더에 저장한다. `.sheet`에 이미 여백이 있으므로 추가 PDF 여백을 중복 지정하지 않는다.
5. `aside.pdf.renderPages`로 **모든 쪽**을 PNG로 렌더링한다. 각 이미지를 직접 확인한다. 자동 치수 검사만으로 시각 검수를 대신하지 않는다.
6. `aside.pdf.extractText`로 문제 번호·정답·성취기준·출처·초안 문구와 쪽수를 확인한다. 학생용에 정답이 없는지, 학생용 다음에 교사용이 오는지 확인한다.
7. 임시 미리보기 서버와 작업용 탭을 정리한다. 구글 문서와 PDF가 다른 조판이면 최신 PDF를 명확히 안내한다. 드라이브 업로드는 실제로 완료했을 때만 완료했다고 말한다.

## 5. 최종 체크

- 질문과 답란이 같은 쪽에 있고, 문항이 단 사이에서 갈라지지 않는가?
- 초등/중등 학년에 맞는 글씨 크기와 손으로 쓰는 공간이 있는가?
- 수식의 지수·곱셈기호·괄호와 한글이 깨지거나 줄 사이에 겹치지 않는가?
- 표 제목과 수식이 어색한 위치에서 줄바꿈되지 않는가?
- 모든 답안선이 균일하게 보이며, 점 격자는 답보다 진하지 않은가?
- 학생용/교사용·문제지/해설이 명확히 구분되고 정답이 잘못 노출되지 않는가?
- 실제 쪽수와 하단 쪽수가 맞고, 본문과 하단 문구가 떨어져 있는가?
- 기존 문항·정답과 대조했고, 슬라이드·교사용 수업 흐름·총시간이 일치하는가?
- 폰트 검사에서 Type3 인라인 글리프를 곧바로 미임베드라고 판단하지 않았는가? PDF 생성 성공·FontFile 개수만으로 임베드나 시각 품질을 단정하지 않는다.
